# Сайт ИНФОТЕХ — pbk.spb.ru

Ветка main выкладывается на сервер автоматически: таймер infotech-sync на ВМ web проверяет её каждые 2 минуты.
Статус выкладки: https://pbk.spb.ru/build.txt. Любой коммит в main сразу уходит в работу — проверяйте страницу перед push.

## Структура
Сайт многостраничный и СОБИРАЕТСЯ генератором — HTML-страницы в public/ руками не править:
    python3 tools/build_site.py
- tools/site/partials/*.html — общие блоки: шапка, подвал, корзина/оформление, тарифы аренды (rent), сопровождение (support),
  сравнение ИТС (its), калькулятор (calc), магазин (shop), главная (hero, about, compare, steps), форма заявки (contact).
  Плейсхолдеры: {{R}} — путь до корня, {{HOME}}, {{SERVICE}}, {{CONTACT_TITLE}}, {{NAV_*}}.
- tools/site/services.py — тексты всех страниц услуг (slug, состав, этапы, блоки, связанные услуги). Новая услуга = новая запись.
- public/assets/site.css, public/assets/site.js — общие стили и скрипт (модули включаются, если на странице есть их блок).
- Страницы: / (главная), /magazin-1c/ (магазин: ?q= ?cat= ?sub= ?e=1), /uslugi/ (все услуги), /uslugi/<slug>/ (услуга), /journal/ (журнал, ?r=рубрика), /journal/<slug>/ (статья), /privacy.html.
- Журнал: content/journal/posts.json (список статей, рубрики cases/1c/servers/infra) + content/journal/<slug>.html (только тело статьи:
  <p>, <h2> → оглавление, <h3>, <ul>/<ol>, <blockquote>). Статьи с датой в будущем публикуются автоматически в этот день.
  Генератор пишет public/journal-posts.json — индекс для внешних скриптов. Кейсы — только реальные, с согласия заказчика.
- Сервер сам запускает tools/build_site.py при каждом новом коммите и раз в сутки (нужен python3); если сборка упала — выкладка не идёт, ошибка в /build.txt.
- public/catalog.js — каталог магазина. НЕ править руками: `python3 tools/update_catalog.py price_1c.xls --out public`
  из прайса фирмы «1С» (столбец «Рекомендованная цена»). Правила отбора — reason() в tools/update_catalog.py.
- tools/own_prices.json — собственные тарифы ИНФОТЕХ (аренда серверов, сопровождение, скидки). После правки — пересобрать catalog.js и сайт.
- public/api/submit.php — приём заказов/заявок; app/lib.php — БД SQLite, почта (SMTP Яндекса), Telegram через мост 127.0.0.1:10809.
- public/admin/ — админка заказов (старая); основной инструмент менеджера — /lk/admin/.
- Личный кабинет /lk/ (PHP, та же SQLite): app/lk.php — общая часть (users, user_companies, otp, documents; колонки orders: user_id, company_id, valid_until, keys_text, has_hw).
  Страницы: /lk/ (дашборд), /lk/login/ (пароль или код на e-mail), /lk/register/ (подтверждение кодом), /lk/orders/ (?n=номер), /lk/documents/, /lk/profile/,
  /lk/support/, /lk/services/ (этап 2), /lk/admin/ (менеджер: статусы, счета/УПД/акты из 1С, ключи, «глазами клиента»), /lk/kp.php (КП в PDF, tFPDF + Inter из app/vendor),
  /lk/file.php (выдача документов с проверкой владельца), /lk/api.php (me, корзина, ИНН→DaData при 'dadata_token' в config.php).
  Заказ с сайта сам привязывается к аккаунту по e-mail (новый аккаунт создаётся); войти в него можно только кодом на этот e-mail.
  Счета, УПД, акты делает 1С:УНФ ИНФОТЕХ — менеджер прикрепляет PDF; счёт на оборудование действует 3 рабочих дня (lk_add_workdays), потом «Срок резерва истёк».
  Сервер: server/lk-setup.sh (nginx /lk/, загрузки 20 МБ, таймер lk-daily 09:05). Документы — app/data/lk-files (не публично).
  Этап 2 (app/lk_services.php, app/lk_admin_services.php): услуги services (server/support/its; тариф INF-SRV-XX / INF-SUP-N из own_prices, paid_until,
  обещанный платёж +3 дня раз за период, config_json, vpn_status, hours_month), service_hours (часы специалиста), tickets/ticket_msgs (обращения с вложениями).
  Продление = заказ с orders.service_id; статус «Оплачен» в /lk/admin/ сам сдвигает paid_until. app/cli-lk-daily.php — напоминания за 7/3/1 день
  (за 7 дней создаёт заказ на продление), просрочка → письмо менеджеру, снятие истёкших резервов. Состояние VPN и сервера менеджер ведёт вручную.
  Оплаты (ТЗ ЛК v2, app/lk_payments.php, app/lk_admin_payments.php): таблица bank_transactions, в orders — paid_amount, invoice_number/date/amount
  (сумма счёта вводится при загрузке PDF счёта). Разнесение: номер заказа ИТ-ггммдд-N или «счёт № X от дата» в назначении → ровно один открытый заказ → проверка ИНН;
  неполная сумма → «Частично оплачен», полная → «Оплачен» + продление услуги. Иначе — /lk/admin/?payments=1 «Неразнесённые», привязка в 1 клик.
  Контур А: вебхук 1С POST /api/v1/payments/callback → public/api/payments-callback.php, HMAC-SHA256(X-Timestamp.".".body), секрет payments_secret в config.php
  (создаёт lk-setup.sh), описание и код для УНФ — docs/1c-payments-webhook.md. Контур В: загрузка выписки 1CClientBankExchange (.txt, Windows-1251).
  Отложено: прямой API Сбера (нужны доступы и сертификаты), QR СБП (нужен эквайринг). Напоминания клиентам в Telegram не делаем (ПД за рубеж).
- CRM, этап 1 — аренда серверов (app/billing.php, app/lk_admin_billing.php → /lk/admin/?billing=1; документ «CRM ИНФОТЕХ: процессы и этапы»):
  счета выставляет ТОЛЬКО CRM, свой номер ИТ-000001 (сквозной), PDF из CRM (реквизиты 'bank' в config.php; без них счёт не выставляется); БП счетов не создаёт, делает УПД статус 2.
  Счёт на следующий месяц — за 5 дней до конца месяца (bill_issue_day), срок — 5-й рабочий день (app/workcal.php: праздники РФ 2026–2027, новые годы — 'holidays' в config).
  Новый клиент с середины месяца — первый счёт пропорционально дням; закрытый доступ сумму не уменьшает. Обещанный платёж: +3 дня, раз на счёт.
  Неоплата: «К отключению» → закрыть доступ = отключить PPP secret на MikroTik + разорвать сессию (app/mikrotik.php, REST 7.1+, 'mikrotik' в config, 'auto' => true — без кнопки);
  через 14 дней закрытого доступа «Выключить ВМ» (вручную на Proxmox/ESXi); через 30 дней после выключения «К удалению» — только вручную, подтверждение именем VPN-учётки.
  Оплата счёта (вебхук/выписка/статус «Оплачен») → paid_until = конец оплаченного месяца → список «Включить» (или авто). cli-lk-daily.php --date=ГГГГ-ММ-ДД — прогон на дату.
- Сотрудники и чат (app/staff.php, app/lk_admin_staff.php): вход в /lk/admin/ — личные учётки staff (логин, ФИО, должность, телефон, дата рождения, e-mail, роль admin/manager).
  Первый вход логином из config (admin_user/admin_password_hash) создаёт учётку администратора; новый хэш в config — аварийное восстановление его пароля.
  Сотрудников добавляет/отключает администратор (?staff=all, ?staff=new), пароль — «Мой профиль» (?me=1). Журналы аренды/оплат подписываются ФИО (mgr_name()).
  Чат (?chat=general | dm:A:B): общий и личные, вложения до 20 МБ в app/data/staff-files (выдача с проверкой участника), опрос ?chat_api каждые 4 с, бейдж непрочитанных.
  Дни рождения — баннер в день рождения и блок «Ближайшие». Старая админка /admin/ по-прежнему по логину из config.
- app/config.php и app/data/ — только на сервере, в репозиторий не попадают (.gitignore).

## Правила
- Телефон во всех формах обязателен, маска +7 (XXX) XXX-XX-XX; сервер принимает только российские номера.
- Электронные поставки — только на e-mail. Позиции: e=1 электронная, e=2 услуга ИНФОТЕХ, e=0 физическая.
- В Telegram не отправлять персональные данные покупателя (серверы за рубежом).
- Не включать в каталог: зарубежные версии, NFR, продукты «1С:Совместимо», 1С:Фреш кроме Базовый/ПРОФ/апгрейд Базовый→ПРОФ, ERP во Фреш,
  а также Агент 1С:Линк, 1С-Финконтроль, Агент резервного копирования 1С:Облачный архив, 1С-Ритейл Чекер, 1С-ЭТП «Астрал-ЭТ», клиентские лицензии «1С-Коннект».

  перенос базы бесплатно на тарифах от 10 000 ₽/мес, дешевле — 4 800 ₽, перенос в рабочее время; лизинга нет; партнёр фирмы «1С»; работаем без НДС (УСН). Не выдумывать другие цифры.

## Регламент: каталог оборудования, поставщики, цены (утверждён заказчиком 13.11.2026)
1. **Парсинг запрещён.** Никаких парсеров, скраперов и подмены User-Agent для чужих сайтов (розничных, конкурентов, поставщиков).
   Источник — только официальные B2B-каналы дистрибьюторов по договору: API, XML/YML-фиды, CSV/Excel-прайсы. Договоры: Marvel, 3Logic.
   Сбор с polus.ru запрещён (ТЗ ЛК, п.6, 14.11.2026) — временный источник polus отключён, не включать.
2. **Свой артикул.** Ключ товара на сайте — только внутренний SKU `PBK-<КАТ>-<NNNNN>` (PBK-CPU-00124, PBK-MBD-00045).
   PartNumber и коды дистрибьюторов — только в таблице соответствия (offers: поставщик + его код → SKU), один товар может закупаться у нескольких.
3. **Наценка.** Закупочные цены на витрину не выводятся. При каждом обновлении — наценка 3,0–5,0% (tools/supply_config.json) и округление вверх до десятков/сотен.
4. **Остатки.** Синхронизируются со складами дистрибьюторов. Три состояния (решение заказчика 13.11.2026):
   в наличии → можно заказать; «под заказ» у поставщика (PreOrder/BackOrder, YML available=false) → можно заказать с пометкой «[под заказ]», срок подтверждает менеджер;
   нет у поставщиков (0) → «Нет в наличии» без оформления или скрытие (флаг out_of_stock); сервер отклоняет заказ на отсутствующий товар.
- Модуль: tools/supply_sync.py, настройки tools/supply_config.json, ключи API — app/data/supply-secrets.json (только на сервере).
