# Сайт ИНФОТЕХ — pbk.spb.ru

Ветка main выкладывается на сервер автоматически: таймер infotech-sync на ВМ web проверяет её каждые 2 минуты.
Статус выкладки: https://pbk.spb.ru/build.txt. Любой коммит в main сразу уходит в работу — проверяйте страницу перед push.

## Структура
Сайт многостраничный и СОБИРАЕТСЯ генератором — HTML-страницы в public/ руками не править:
    python3 tools/build_site.py
- tools/site/partials/*.html — общие блоки: шапка, подвал, корзина/оформление, тарифы аренды (rent), сопровождение (support),
  сравнение ИТС (its), калькулятор (calc), магазин (shop), главная (hero, about, compare, steps), форма заявки (contact).
  Плейсхолдеры: {{R}} — путь до корня, {{HOME}}, {{SERVICE}}, {{CONTACT_TITLE}}, {{NAV_*}}.
- tools/site/services.py — тексты всех страниц услуг (slug, состав, этапы, блоки, связанные услуги). Новая услуга = новая запись.
- public/assets/site.css, public/assets/site.js — общие стили и скрипт (модули включаются, если на странице есть их блок).
- Страницы: / (главная), /magazin-1c/ (магазин: ?q= ?cat= ?sub= ?e=1), /uslugi/ (все услуги), /uslugi/<slug>/ (услуга), /journal/ (журнал, ?r=рубрика), /journal/<slug>/ (статья), /privacy.html.
- Журнал: content/journal/posts.json (список статей, рубрики cases/1c/servers/infra) + content/journal/<slug>.html (только тело статьи:
  <p>, <h2> → оглавление, <h3>, <ul>/<ol>, <blockquote>). Статьи с датой в будущем публикуются автоматически в этот день.
  Генератор пишет public/journal-posts.json — индекс для внешних скриптов. Кейсы — только реальные, с согласия заказчика.
- Сервер сам запускает tools/build_site.py при каждом новом коммите и раз в сутки (нужен python3); если сборка упала — выкладка не идёт, ошибка в /build.txt.
- public/catalog.js — каталог магазина. НЕ править руками: `python3 tools/update_catalog.py price_1c.xls --out public`
  из прайса фирмы «1С» (столбец «Рекомендованная цена»). Правила отбора — reason() в tools/update_catalog.py.
- tools/own_prices.json — собственные тарифы ИНФОТЕХ (аренда серверов, сопровождение, скидки). После правки — пересобрать catalog.js и сайт.
- public/api/submit.php — приём заказов/заявок; app/lib.php — БД SQLite, почта (SMTP Яндекса), Telegram через мост 127.0.0.1:10809.
- public/admin/ — админка заказов.
- app/config.php и app/data/ — только на сервере, в репозиторий не попадают (.gitignore).

## Регламент: каталог оборудования, поставщики, цены (утверждён заказчиком 13.11.2026)
1. **Парсинг запрещён.** Никаких парсеров, скраперов и подмены User-Agent для чужих сайтов (розничных, конкурентов, поставщиков).
   Источник — только официальные B2B-каналы дистрибьюторов по договору: API, XML/YML-фиды, CSV/Excel-прайсы (3Logic, Merlion, Netlab и др.).
2. **Свой артикул.** Ключ товара на сайте — только внутренний SKU `PBK-<КАТ>-<NNNNN>` (PBK-CPU-00124, PBK-MBD-00045).
   PartNumber и коды дистрибьюторов — только в таблице соответствия (offers: поставщик + его код → SKU), один товар может закупаться у нескольких.
3. **Наценка.** Закупочные цены на витрину не выводятся. При каждом обновлении — наценка 3,0–5,0% (tools/supply_config.json) и округление вверх до десятков/сотен.
4. **Остатки.** Синхронизируются со складами дистрибьюторов. Остаток 0 → «Под заказ» без возможности оформить заказ или скрытие (флаг out_of_stock); сервер отклоняет заказ на отсутствующий товар.
- Модуль: tools/supply_sync.py, настройки tools/supply_config.json, ключи API — app/data/supply-secrets.json (только на сервере).
